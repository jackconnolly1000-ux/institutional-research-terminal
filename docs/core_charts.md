# Two core chart questions — Release 1 step 6

The app and each primary company workbook answer the same two questions from the reconciled models; all existing company-specific cash, payment and maturity charts remain.

1. **What remained after capital spending?** TTM OCF, negative capital spending (a use), and signed FCF. FCF = OCF − spending; it is the result, not a third cash flow to add. Exact twelve-month dates and units are visible. Oracle retains negative FCF. No forecast, normalized recurring flow or repayment coverage is inferred.
2. **How did borrowing and cash change?** LLY/ORCL compare their checked annual and latest balance sheets. VST compares cash only: its older borrowing presentation is unchecked, so no zero or debt trend is fabricated. Cash excludes restricted cash and investments; borrowing excludes leases. The dates and limitations are beside the chart.

`core_charts.py` consumes the checked history/ratio models. The app uses responsive signed horizontal bars and explicit numbers. `tests/offline/core_chart_sheet.mjs` adds two native column charts and their formula-backed source tables to **Core charts**. Excel stores whole USD and displays millions; the app displays billions. Excel chart axis labels use the same million scaling as the source tables. Series colors identify categories, not funding strength.

**App balance chart, revised October 17, 2026.** "How did borrowing and cash change?" now shows one panel per balance (cash, then baseline borrowing), each with both dates on one shared zero-based scale. All values are balances, so the earlier diverging layout left half the width empty. Each panel states its change since the annual date. Cash is blue (`theme.SERIES_CASH`, #3987e5) and baseline borrowing orange (`theme.SERIES_BORROWING`, #d95926), with matching swatches beside the same headline figures. These colors identify the quantity; they don't grade it. The pair passes the dataviz six checks on both dark surfaces (all-pairs CVD ΔE 26.8, normal-vision ΔE 31.8, ≥ 3:1 contrast). Panel titles carry the identity too, so color is never alone. Vistra shows cash only, because its older borrowing is Unavailable. The chart model, workbook charts and their values are unchanged; the three manifests' `charts_sha256` is rebound because the rendering code is fingerprinted.

The flow table links to Debt and liquidity B10:B12, reversing the capex sign for display only. The balance table links to History B6:C7, omitting unsupported older VST debt entirely. The builder changes an OCF input temporarily, checks that both plotted OCF and FCF recalculate, then restores the source before export. Tests check native chart count, series count, signed data, source bindings and source/model fingerprints. Rendered chart sheets and About additions are inspected for all three companies, with app fragments at desktop and phone widths. Downloads refuse stale chart/history fingerprints. Existing inputs and financial conclusions are unchanged.

Scope: two dated observations do not establish a continuous trend. Annual and later TTM windows overlap as explained on History; the balance chart uses instants only. More companies, forecasts, normalized cash flow and automated refresh remain outside this release.
